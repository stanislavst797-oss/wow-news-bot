# wow-news-bot

Два независимых бота на GitHub Actions — в облаке, круглосуточно, компьютер не нужен.

| Бот | Что делает | Канал | Расписание |
|---|---|---|---|
| **Новости** (`bot.py`) | посты из RSS [noob-club.ru](https://www.noob-club.ru/rss2.xml) | #новости | каждые 5 минут |
| **Тир-листы** (`tierlist.py`) | тир-листы и таблицы рейтингов Mythic+ с [archon.gg](https://www.archon.gg) по трём ролям | #mythic-tier-list и каналы ролей | ежедневно, 06:00 UTC |

Боты не пересекаются: разные файлы, разные воркфлоу, разные секреты,
разные concurrency-группы. Поломка одного не трогает другой.

# Бот новостей

Автопостинг новостей World of Warcraft из RSS [noob-club.ru](https://www.noob-club.ru/rss2.xml)
в Discord-канал **#новости** (сервер Wow Key).

## Как это устроено

| Файл | Зачем |
|---|---|
| `bot.py` | забирает ленту, фильтрует, шлёт в Discord |
| `config.json` | стоп-слова и настройки — правится без правки кода |
| `posted.json` | что уже отправлено (последние 500 ссылок), состояние между запусками |
| `requirements.txt` | зависимости с зафиксированными версиями |
| `.github/workflows/news.yml` | расписание и запуск |

Расписание — `*/5`, то есть каждые 5 минут: это минимально допустимый интервал в GitHub Actions.

Расписание в Actions — **best-effort**: GitHub пропускает часть срабатываний под нагрузкой,
поэтому реальная задержка между публикацией на сайте и постом в канале плавает.
Просить чаще — единственный доступный способ её уменьшить.

Вебхук в репозитории не хранится. Он лежит в GitHub Secrets под именем `DISCORD_WEBHOOK`
и попадает в задачу переменной окружения.

## Что бот делает и чего не делает

* Отправляет **только** заголовок, короткий анонс (до 300 символов) и ссылку на оригинал.
  Полные тексты статей не публикуются.
* Отбрасывает новости, у которых в заголовке есть стоп-слово (Diablo, Overwatch,
  Hearthstone, StarCraft, Rumble и русские написания).
* Не спамит архивом: при самом первом запуске просто запоминает текущие ссылки.
* За один прогон отправляет максимум 5 новостей, остальное уходит в следующий.
* Если сайт или сеть недоступны — пишет это в лог и завершается успешно, не роняя задачу.

## Повседневные операции

Все команды — из папки репозитория.

Посмотреть последние прогоны:

```bash
gh run list --workflow=news.yml --limit 10
```

Логи последнего прогона:

```bash
gh run view --log
```

Запустить прямо сейчас, не дожидаясь расписания:

```bash
gh workflow run news.yml
```

Поставить на паузу:

```bash
gh workflow disable news.yml
```

Снять с паузы:

```bash
gh workflow enable news.yml
```

## Поменять стоп-слова

Правится `config.json`, код трогать не надо — список подхватывается на следующем прогоне.
Совпадение ищется по вхождению в заголовок, регистр не важен.

```bash
git pull
# отредактировать config.json
git commit -am "фильтр: правки стоп-слов"
git push
```

Там же меняются `max_per_run` (сколько новостей за прогон), `description_limit`
(длина анонса) и `embed_color` (цвет полоски эмбеда, десятичное число).

## Если прогон покраснел

Красный прогон бывает по двум причинам, обе видны в логе первой же строкой с `ERROR`.

**«вебхук недействителен»** — вебхук удалён или перевыпущен в Discord.
Создайте новый в настройках канала #новости и обновите секрет:

```bash
gh secret set DISCORD_WEBHOOK
```

**«конфликт по posted.json»** — кто-то правил состояние руками одновременно с ботом.
Само по себе не страшно: следующий прогон может повторить одну новость. Достаточно
`git pull` и убедиться, что `posted.json` валидный.

Недоступность сайта или сети прогон **не** красит — бот логирует это и выходит с кодом 0,
следующая попытка через 5 минут.

## Начать историю заново

Если удалить `posted.json` и запушить, следующий прогон посчитает себя первым:
запомнит текущие 10 ссылок и ничего не отправит. Дальше пойдут только свежие новости.

## Локальный запуск

```bash
pip install -r requirements.txt
DRY_RUN=1 python bot.py
```

`DRY_RUN=1` прогоняет всю логику, но ничего не отправляет в Discord.
Для реальной отправки нужна переменная `DISCORD_WEBHOOK`.

# Бот тир-листа Mythic+

Раз в сутки обходит три роли — **ДД, танки, хилы** — и для каждой снимает две картинки
с [archon.gg](https://www.archon.gg): плитки тир-листа S/A/B/C и таблицу рейтингов.
Обе картинки роли уходят **одним сообщением**, и у каждой роли **своё сообщение,
которое обновляется**, а не создаётся заново.

Один прогон обрабатывает все роли последовательно. Если одна упала, остальные всё равно
обрабатываются, но прогон в итоге **красный** — в конце лога перечислено, какая роль
и почему. Молча пропустить роль бот не может.

| Файл | Зачем |
|---|---|
| `tierlist.py` | снимает обе картинки и публикует |
| `tierlist_config.json` | список ролей (`targets`) и общие настройки (`defaults`) |
| `tierlist_state.json` | ID сообщений по ролям (`roles.dps`, `roles.tank`, …) |
| `requirements-tierlist.txt` | зависимости с зафиксированными версиями |
| `.github/workflows/tierlist.yml` | расписание и запуск |

Расписание — ежедневно в 06:00 UTC (09:00 МСК). Archon пересчитывает данные
несколько раз в сутки («Last updated: N hours ago»), поэтому недельный снимок
большую часть времени был бы устаревшим.

Перед съёмкой бот закрывает рекламный баннер «HEY THERE… disabling your Adblock»:
сначала штатным крестиком, затем стилями, а потом отдельно проверяет, что поверх
кадра ничего не осталось. Если осталось — прогон краснеет, а не шлёт перекрытую картинку.

## Роли: как добавить, убрать или перенастроить

Все роли описаны списком `targets` в `tierlist_config.json`. У каждой цели:

| Поле | Что значит |
|---|---|
| `role` | короткий идентификатор, по нему называются файлы и хранится ID сообщения |
| `name` | как роль зовётся в логах |
| `url` | адрес страницы на Archon |
| `webhook_env` | имя секрета с вебхуком канала |
| `caption_title` | подпись под картинками |
| `min_specs`, `min_rankings_rows` | пороги «данные действительно набрались» |

Пороги отдельные не для красоты: у ДД 27 специализаций, у танков 6, у хилов 7.
Общий порог в 15 уронил бы обе короткие роли.

**Чтобы добавить четвёртую роль**, допишите объект в `targets`, положите вебхук
в секреты и добавьте одну строку в блок `env` шага «Run tier list bot»
в `.github/workflows/tierlist.yml`. Код править не нужно.

```bash
gh secret set NEW_ROLE_WEBHOOK
```

**Чтобы сменить уровень ключа, раздел или период** у существующей роли — это части `url`:

```
https://www.archon.gg/wow/tier-list/{РОЛЬ}/mythic-plus/{УРОВЕНЬ}/all-dungeons/{ПЕРИОД}
```

| Часть | Варианты |
|---|---|
| РОЛЬ | `dps-rankings`, `tank-rankings`, `healer-rankings` |
| УРОВЕНЬ | служебный идентификатор Archon, не номер ключа |
| ПЕРИОД | `this-week`, `last-week` |

Меняя `url`, поправьте и `caption_title` — подпись не подставляется автоматически.
Селекторы менять **не надо**: вёрстка у всех ролей одинаковая, поиск секций идёт
по структуре, а не по слову «DPS».

```bash
git pull
# отредактировать tierlist_config.json
git commit -am "тир-лист: правки ролей"
git push
gh workflow run tierlist.yml
```

## Как понять по логам, что сайт изменился

Успешный прогон всегда пишет такие опорные строки:

```
ролей к обработке: 3
--- роль «ДД» (dps) ---
секция «DPS Tier List for Mythic+»: тиров 4, специализаций 27
закрыто рекламных блоков крестиком: 2
подписал названиями все 27 специализаций
секция «DPS Rankings for Mythic+»: колонки Specialization | Max Key | DPS | M+ Score | Popularity | Parses, строк всего 27, показываю 15
...
итог: успешно 3 из 3
```

Тревожные признаки:

**Прогон красный, в логе «таблица не отрисовалась»** — сайт переименовал классы.
В сообщении указано, что именно не нашлось: найден ли контейнер, сколько тиров
и специализаций насчиталось, сколько осталось незагруженных ленивых блоков.
Чинится правкой `section_selector` / `tier_selector` / `spec_selector`
в `tierlist_config.json`. Как найти новые имена: открыть страницу в браузере,
инспектор → найти блок тир-листа. Годятся только классы **без хэша**
(`builds-tier-list-section`), а не CSS-модули вида `Layout_main__kfZRU` —
у последних суффикс меняется при каждой пересборке сайта.

**Прогон зелёный, но в логе «подписал названиями 0 из 27»** — сайт убрал
подсказку `title` у ячеек. Картинка уйдёт, но без названий специализаций.
Чинится правкой `JS_INJECT_NAMES` в `tierlist.py`.

**Прогон красный, в логе «СБОЙ <роль> — …»** — сломалась одна конкретная роль,
остальные при этом отработали. Причина указана там же; смотрите артефакт именно
этой роли (`tierlist-tank.png` и т.п.).

**Прогон красный, «осталась реклама поверх содержимого»** — Archon добавил новый
рекламный слой, которого нет в `ad_selectors`. В сообщении указан его класс:
добавьте соответствующий `[class*="..."]` в `ad_selectors` в `tierlist_config.json`.

**Прогон красный, «в таблицу рейтингов попало всего N строк»** — сайт переименовал
кнопку «Show More», которой бот раскрывает список. Правится `JS_EXPAND_ROWS` в `tierlist.py`.

**Прогон красный, «картинка почти одноцветная»** — блок нашёлся, но отрисовался
пустым. Обычно это значит, что сайт стал грузить данные иначе.

В любом случае сначала посмотрите артефакт прогона — там лежит именно то,
что снялось, по всем ролям:

```bash
gh run download --name tierlist-screenshots
```

## Начать сообщение заново

Удалите `tierlist_state.json` (или только нужную роль из `roles`) и запушьте —
следующий прогон создаст новое сообщение и запомнит его ID. Старое останется
висеть в канале, его удалите руками.

## Локальный запуск

```bash
pip install -r requirements-tierlist.txt
python -m playwright install chromium
DRY_RUN=1 python tierlist.py
```

`DRY_RUN=1` снимает скриншот в `tierlist.png` и прогоняет все проверки,
но в Discord ничего не отправляет.
